Use case: ui-mockup
Asset type: independent desktop concept for the production Researcher / Infinibay web application.
Create a realistic, production-quality Spanish UI at a natural 1440 x 1024 desktop viewport, flat front-on app content only. This is one full screen, not a presentation board. Professional research and software workbench for an owner working with agents. It must make evidence, assumptions and user corrections distinguishable, without jargon overload.
Target screen: /tasks, selected research task #24, "Comprobar los reintentos". Anonymous fixture project "Atlas"; these are explicitly design fixtures, not real activity. Date anchor: 2026-10-31; omit relative dates. No provided screenshots or reference images: this is a new design direction grounded in existing code and the brief below.
Core interaction: browse tasks, read a selected task, understand a finding and its source, correct the context, explicitly start or stop a run. One primary action. Use task rows, simple separators, strong typography, whitespace and purposeful alignment; avoid cards inside cards.
Content to communicate accurately: a native result is a proposal, not accepted completion. The selected task has status "Propuesta para revisar"; agent completion never silently marks it done. Show evidence and limitation plainly:
"Hallazgo provisional"
"Un reintento podría repetir el envío."
"Ejemplo: se guarda el mensaje, se pierde la respuesta y el cliente vuelve a enviarlo."
"Fuente: registro de prueba · líneas 18–24"
"Hipótesis: falta una clave estable. Todavía no está comprobado."
User correction: "Los reintentos del cliente ya comparten la misma clave."
Explicit response: "Revisaré el servidor con esa condición. La propuesta anterior conserva su contexto."
Show an understated readable causal diagram as actual content: "Guardar → Respuesta perdida → Reintentar", with a text explanation. Correction control "Corregir contexto" and input label "Qué quieres comprobar". Primary action "Iniciar trabajo"; no fake claim that generation is active, no decorative activity stats.
Shared app name "Researcher", project selector "Atlas", navigation items grouped by work and knowledge, /tasks active. Fit clear navigation while allowing less relevant destinations to exist off-screen.
Body typography 14–16px, comfortably readable, at most two typefaces. Long-form line length around 60 characters. Primary controls at least 40px high. Restrained neutral palette with one functional accent; status has text as well as color.
Avoid generic AI dashboard aesthetics, purple gradients, glow, glassmorphism, gratuitous avatars, sparkles, hero slogans, marketing copy, invented metrics, tiny illegible gray text, nested cards, pervasive pills and huge empty ornamental areas. No watermark, browser chrome or "AI-powered"/"made by AI". Render key Spanish text carefully; simplify secondary detail before crowding the canvas.

Direction: Composition: a graphite and ink dark working surface with a slim top project/navigation bar. Use a contained three-column work board "Pendiente", "En curso", "Para revisar" across the upper third with compact task rows, NOT a full screen of repeated colorful cards. Selected task #24 sits in "Para revisar". Light high-contrast type, warm off-white readable body text, restrained muted cyan accent. "Iniciar trabajo" is the only high-contrast filled button in a small request composer along the bottom; secondary interventions have quiet outlined controls. Show task status and context without fake motion or dense telemetry. This alternative should favor a cross-task operational overview and a broad evidence work area, genuinely different from a list-plus-inspector.
